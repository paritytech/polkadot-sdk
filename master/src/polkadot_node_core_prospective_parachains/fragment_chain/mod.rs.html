17//! Utility for managing parachain fragments not referenced by the relay-chain.
18//!
19//! # Overview
20//!
21//! The main type exposed by this module is the [`FragmentChain`].
22//!
23//! Each fragment chain is associated with a particular relay chain block (called scheduling
24//! parent). Fragment chains are created for each active leaf and retained as long as the block
25//! remains in the ancestry of any active leaf. Its configuration is split into two parts:
26//! - A [`SchedulingScope`] shared across all parachains, containing the scheduling parent block and
27//!   its ancestors (up to `scheduling_lookahead - 1`, bounded by session boundaries) —
28//!   `scheduling_lookahead` blocks in total. Prior to V3 descriptors, both the relay parent and the
29//!   scheduling parent need to be within this scope. With v3 descriptors, they may differ, and the
30//!   relay parent may be much older (up to `HostConfiguration.max_relay_parent_session_age`)
31//!   sessions old.
32//!
33//! - A [`Scope`] per parachain, containing the base constraints derived from the latest included
34//!   candidate, the candidates pending availability, and the maximum chain length.
35//!
36//! Each parachain has a single `FragmentChain` for each scheduling parent block in the view where
37//! it is scheduled.
38//!
39//! A fragment chain consists of two parts: the **chain** and the **unconnected storage**.
40//!
41//! The **chain** is a linear sequence of backed candidates building on top of each other, starting
42//! from the candidates pending availability (which form the prefix). The chain has a maximum
43//! length of `pending_availability_count + claim_queue_depth`, where `claim_queue_depth` is the
44//! number of claim queue slots this parachain occupies across all assigned cores. Only backed
45//! candidates may be added to the chain, and in the presence of forks, the fork selection rule
46//! determines which candidate is chosen.
47//!
48//! The **unconnected storage** holds seconded and backable candidates that may be added to the
49//! chain in the future. When a candidate is first seconded, it enters this storage. Only after it
50//! reaches the backing quorum may it be promoted to the chain — and only if it builds on the
51//! chain tip and is preferred by the fork selection rule.
52//!
53//! Candidates in the unconnected storage may have any relationship between them: they may form
54//! trees, be completely unrelated, or even form cycles. This is intentional — it allows
55//! parallelizing the backing process across different groups (for elastic scaling) and accepting
56//! parachain forks before a winner is determined.
57//!
58//! We accept parachain forks only if the fork selection rule allows for it. In other words, if we
59//! have a backed candidate, we begin seconding/validating a fork only if it has a lower candidate
60//! hash. Once both forks are backed, we discard the one with the higher candidate hash.
61//! We assume all validators pick the same fork according to the fork selection rule. If we decided
62//! to not accept parachain forks, candidates could end up getting only half of the backing votes or
63//! even less (for forks of larger arity). This would affect the validator rewards. Still, we don't
64//! guarantee that a fork-producing parachain will be able to fully use elastic scaling.
65//!
66//! Once a candidate is backed and becomes part of the chain, we trim from the unconnected storage
67//! any candidates that constitute forks on the chain and no longer have potential.
68//!
69//! This module also makes use of types provided by the Inclusion Emulator module, such as
70//! [`Fragment`] and [`Constraints`]. These perform the actual job of checking for validity of
71//! prospective fragments.
72//!
73//! # Fork choice rule
74//!
75//! The current rule is: choose the candidate with the lower candidate hash.
76//!
77//! # Parachain cycles
78//!
79//! Parachains can create cycles, because:
80//!   1. There's no requirement that head-data is unique for a parachain. Furthermore, a parachain
81//!      is under no obligation to be acyclic, and this is mostly just because it's totally
82//!      inefficient to enforce it. Practical use-cases are acyclic, but there is still more than
83//!      one way to reach the same head-data.
84//!   2. Candidates only refer to their parent by its head-data. This whole issue could be resolved
85//!      by having candidates reference their parent by candidate hash.
86//!
87//! However, dealing with cycles increases complexity during the backing/inclusion process for no
88//! practical reason.
89//! These cycles may be accepted by fragment chains while candidates are part of the unconnected
90//! storage, but they will definitely not make it to the chain.
91//!
92//! On the other hand, enforcing that a parachain will NEVER be acyclic would be very complicated
93//! (looping through the entire parachain's history on every new candidate or changing the candidate
94//! receipt to reference the parent's candidate hash).
95//!
96//! Therefore, we don't provide a guarantee that a cycle-producing parachain will work (although in
97//! practice they probably will if the cycle length is larger than the number of assigned cores
98//! multiplied by two).
99//!
100//! # Spam protection
101//!
102//! As long as the supplied number of candidates is bounded, [`FragmentChain`] complexity is
103//! bounded. This means that higher-level code needs to be selective about limiting the amount of
104//! candidates that are considered.
105//!
106//! Practically speaking, the collator-protocol will limit the number of fetched collations per
107//! core, to the number of claim queue assignments for the paraid on that core.
108//! Statement-distribution will not allow more than `scheduler_params.lookahead` seconded candidates
109//! at a scheduling parent per each validator in the backing group.
110//!
111//! The code in this module is not designed for speed or efficiency, but conceptual simplicity.
112//! Our assumption is that the amount of candidates and parachains we consider will be reasonably
113//! bounded and in practice will not exceed a few thousand at any time. This naive implementation
114//! will still perform fairly well under these conditions, despite being somewhat wasteful of
115//! memory.
116//!
117//! Still, the expensive candidate data (CandidateCommitments) are wrapped in an `Arc` and shared
118//! across fragment chains of the same para on different active leaves.

144/// Fragment chain related errors.
145#[derive(Debug, Clone, PartialEq, Error)]
146pub(crate) enum Error {
147	#[error("Candidate already known")]
148	CandidateAlreadyKnown,
149	#[error("Candidate's parent head is equal to its output head. Would introduce a cycle.")]
150	ZeroLengthCycle,
151	#[error("Candidate would introduce a cycle")]
152	Cycle,
153	#[error("Candidate would introduce two paths to the same output state")]
154	MultiplePaths,
155	#[error("Attempting to directly introduce a Backed candidate. It should first be introduced as Seconded")]
156	IntroduceBackedCandidate,
157	#[error("Relay parent {0:?} of the candidate precedes the relay parent {1:?} of a pending availability candidate")]
158	RelayParentPrecedesCandidatePendingAvailability(Hash, Hash),
159	#[error("Candidate would introduce a fork with a pending availability candidate: {0:?}")]
160	ForkWithCandidatePendingAvailability(CandidateHash),
161	#[error("Fork selection rule favours another candidate: {0:?}")]
162	ForkChoiceRule(CandidateHash),
163	#[error("Could not find parent of the candidate")]
164	ParentCandidateNotFound,
165	#[error("Could not compute candidate constraints: {0:?}")]
166	ComputeConstraints(inclusion_emulator::ModificationError),
167	#[error("Candidate violates constraints: {0:?}")]
168	CheckAgainstConstraints(inclusion_emulator::FragmentValidityError),
169	#[error("Relay parent would move backwards from the latest candidate in the chain")]
170	RelayParentMovedBackwards,
171	#[error(transparent)]
172	CandidateEntry(#[from] CandidateEntryError),
173	#[error("Relay parent {0:?} not in scope")]
174	RelayParentNotInScope(Hash),
175	#[error("Scheduling parent {0:?} not in scope")]
176	SchedulingParentNotInScope(Hash),
177}

180	fn is_relay_block_not_in_scope(&self) -> bool {
181		matches!(self, Error::RelayParentNotInScope(_) | Error::SchedulingParentNotInScope(_))
182	}

185/// The rule for selecting between two backed candidate forks, when adding to the chain.
186/// All validators should adhere to this rule, in order to not lose out on rewards in case of
187/// forking parachains.
188fn fork_selection_rule(hash1: &CandidateHash, hash2: &CandidateHash) -> Ordering {
189	hash1.cmp(hash2)
190}

192/// Utility for storing candidates and information about them such as their relay-parents and their
193/// backing states. This does not assume any restriction on whether or not the candidates form a
194/// chain. Useful for storing all kinds of candidates.
195#[derive(Clone, Default)]
196pub(crate) struct CandidateStorage {
197	// Index from head data hash to candidate hashes with that head data as a parent. Useful for
198	// efficiency when responding to `ProspectiveValidationDataRequest`s or when trying to find a
199	// new candidate to push to a chain.
200	by_parent_head: HashMap<Hash, HashSet<CandidateHash>>,
201
202	// Index from head data hash to candidate hashes outputting that head data. For
203	// efficiency when responding to `ProspectiveValidationDataRequest`s.
204	by_output_head: HashMap<Hash, HashSet<CandidateHash>>,
205
206	// Index from candidate hash to fragment node.
207	by_candidate_hash: HashMap<CandidateHash, CandidateEntry>,
208}
209
210impl CandidateStorage {
211	/// Introduce a new pending availability candidate.
212	pub fn add_pending_availability_candidate(
213		&mut self,
214		candidate_hash: CandidateHash,
215		candidate: CommittedCandidateReceipt,
216		persisted_validation_data: PersistedValidationData,
217	) -> Result<(), Error> {
218		let entry = CandidateEntry::new(
219			candidate_hash,
220			candidate,
221			persisted_validation_data,
222			CandidateState::Backed,
223		)?;
224
225		self.add_candidate_entry(entry)
226	}
227
228	/// Return the number of stored candidates.
229	pub fn len(&self) -> usize {
230		self.by_candidate_hash.len()
231	}
232
233	/// Introduce a new candidate entry.
234	fn add_candidate_entry(&mut self, candidate: CandidateEntry) -> Result<(), Error> {
235		let candidate_hash = candidate.candidate_hash;
236		if self.by_candidate_hash.contains_key(&candidate_hash) {
237			return Err(Error::CandidateAlreadyKnown);
238		}
239
240		self.by_parent_head
241			.entry(candidate.parent_head_data_hash)
242			.or_default()
243			.insert(candidate_hash);
244		self.by_output_head
245			.entry(candidate.output_head_data_hash)
246			.or_default()
247			.insert(candidate_hash);
248		self.by_candidate_hash.insert(candidate_hash, candidate);
249
250		Ok(())
251	}
252
253	/// Remove a candidate from the store.
254	fn remove_candidate(&mut self, candidate_hash: &CandidateHash) {
255		if let Some(entry) = self.by_candidate_hash.remove(candidate_hash) {
256			if let Entry::Occupied(mut e) = self.by_parent_head.entry(entry.parent_head_data_hash) {
257				e.get_mut().remove(&candidate_hash);
258				if e.get().is_empty() {
259					e.remove();
260				}
261			}
262
263			if let Entry::Occupied(mut e) = self.by_output_head.entry(entry.output_head_data_hash) {
264				e.get_mut().remove(&candidate_hash);
265				if e.get().is_empty() {
266					e.remove();
267				}
268			}
269		}
270	}
271
272	/// Note that an existing candidate has been backed.
273	fn mark_backed(&mut self, candidate_hash: &CandidateHash) {
274		if let Some(entry) = self.by_candidate_hash.get_mut(candidate_hash) {
275			gum::trace!(target: LOG_TARGET, ?candidate_hash, "Candidate marked as backed");
276			entry.state = CandidateState::Backed;
277		} else {
278			gum::trace!(target: LOG_TARGET, ?candidate_hash, "Candidate not found while marking as backed");
279		}
280	}
281
282	/// Whether a candidate is contained within the storage already.
283	fn contains(&self, candidate_hash: &CandidateHash) -> bool {
284		self.by_candidate_hash.contains_key(candidate_hash)
285	}
286
287	/// Return an iterator over references to the stored candidates, in arbitrary order.
288	fn candidates(&self) -> impl Iterator<Item = &CandidateEntry> {
289		self.by_candidate_hash.values()
290	}
291
292	/// Try getting head-data by hash.
293	fn head_data_by_hash(&self, hash: &Hash) -> Option<&HeadData> {
294		// First, search for candidates outputting this head data and extract the head data
295		// from their commitments if they exist.
296		//
297		// Otherwise, search for candidates building upon this head data and extract the head data
298		// from their persisted validation data if they exist.
299		self.by_output_head
300			.get(hash)
301			.and_then(|m| m.iter().next())
302			.and_then(|a_candidate| self.by_candidate_hash.get(a_candidate))
303			.map(|e| &e.candidate.commitments.head_data)
304			.or_else(|| {
305				self.by_parent_head
306					.get(hash)
307					.and_then(|m| m.iter().next())
308					.and_then(|a_candidate| self.by_candidate_hash.get(a_candidate))
309					.map(|e| &e.candidate.persisted_validation_data.parent_head)
310			})
311	}
312
313	/// Returns the backed candidates which have the given head data hash as parent.
314	fn possible_backed_para_children<'a>(
315		&'a self,
316		parent_head_hash: &'a Hash,
317	) -> impl Iterator<Item = &'a CandidateEntry> + 'a {
318		let by_candidate_hash = &self.by_candidate_hash;
319		self.by_parent_head
320			.get(parent_head_hash)
321			.into_iter()
322			.flat_map(|hashes| hashes.iter())
323			.filter_map(move |h| {
324				by_candidate_hash.get(h).and_then(|candidate| {
325					(candidate.state == CandidateState::Backed).then_some(candidate)
326				})
327			})
328	}
329}

351#[derive(Debug, Clone)]
352/// Representation of a candidate into the [`CandidateStorage`].
353/// A candidate entry, containing information about a candidate and its state.
354///
355/// For V3 candidate descriptors, this tracks both the relay_parent and scheduling_parent:
356/// - **relay_parent**: Determines execution context (messages, config, etc.). Can be old/finalized.
357/// - **scheduling_parent**: Determines scheduling context (backing group, core). Must be recent.
358///
359/// For V1/V2 candidates, both fields contain the same value (relay_parent).
360///
361/// The fragment chain validates that relay_parent is within the allowed ancestry scope.
362pub(crate) struct CandidateEntry {
363	candidate_hash: CandidateHash,
364	parent_head_data_hash: Hash,
365	output_head_data_hash: Hash,
366	/// The relay parent hash. For V3, this is the execution parent and can be older.
367	relay_parent: Hash,
368	scheduling_parent: Hash,
369	para_id: ParaId,
370	candidate: Arc<ProspectiveCandidate>,
371	state: CandidateState,
372}
373
374impl CandidateEntry {
375	/// Create a new seconded candidate entry.
376	pub fn new_seconded(
377		candidate_hash: CandidateHash,
378		candidate: CommittedCandidateReceipt,
379		persisted_validation_data: PersistedValidationData,
380	) -> Result<Self, CandidateEntryError> {
381		Self::new(candidate_hash, candidate, persisted_validation_data, CandidateState::Seconded)
382	}
383
384	pub fn hash(&self) -> CandidateHash {
385		self.candidate_hash
386	}
387
388	fn new(
389		candidate_hash: CandidateHash,
390		candidate: CommittedCandidateReceipt,
391		persisted_validation_data: PersistedValidationData,
392		state: CandidateState,
393	) -> Result<Self, CandidateEntryError> {
394		let para_id = candidate.descriptor.para_id();
395		if persisted_validation_data.hash() != candidate.descriptor.persisted_validation_data_hash()
396		{
397			return Err(CandidateEntryError::PersistedValidationDataMismatch);
398		}
399
400		let parent_head_data_hash = persisted_validation_data.parent_head.hash();
401		let output_head_data_hash = candidate.commitments.head_data.hash();
402
403		if parent_head_data_hash == output_head_data_hash {
404			return Err(CandidateEntryError::ZeroLengthCycle);
405		}
406
407		let relay_parent = candidate.descriptor.relay_parent();
408		let scheduling_parent = candidate.descriptor.scheduling_parent();
409
410		Ok(Self {
411			candidate_hash,
412			parent_head_data_hash,
413			output_head_data_hash,
414			relay_parent,
415			scheduling_parent,
416			state,
417			candidate: Arc::new(ProspectiveCandidate {
418				commitments: candidate.commitments,
419				persisted_validation_data,
420				pov_hash: candidate.descriptor.pov_hash(),
421				validation_code_hash: candidate.descriptor.validation_code_hash(),
422			}),
423			para_id,
424		})
425	}
426
427	fn relay_parent_info(&self) -> RelayParentInfo {
428		RelayParentInfo {
429			hash: self.relay_parent,
430			number: self.candidate.persisted_validation_data.relay_parent_number,
431			storage_root: self.candidate.persisted_validation_data.relay_parent_storage_root,
432		}
433	}
434}

461/// An error variant indicating that ancestors provided to a scope
462/// had unexpected order.
463#[derive(Debug)]
464pub(crate) struct UnexpectedAncestor {
465	/// The block number that this error occurred at.
466	/// Allow as dead code, but it's being read in logs.
467	#[allow(dead_code)]
468	pub number: BlockNumber,
469	/// The previous seen block number, which did not match `number`.
470	/// Allow as dead code, but it's being read in logs.
471	#[allow(dead_code)]
472	pub prev: BlockNumber,
473}
474
475impl SchedulingScope {
476	/// Create a new [`SchedulingScope`].
477	///
478	/// Ancestors should be in reverse order, starting with the parent
479	/// of the `scheduling_parent`, and proceeding backwards in block number
480	/// increments of 1. Ancestors not following these conditions will be
481	/// rejected.
482	///
483	/// All provided ancestors will be included in the scope. The caller is responsible
484	/// for providing the correct set of ancestors (typically limited by session boundaries
485	/// and scheduling lookahead).
486	///
487	/// It is allowed to provide zero ancestors.
488	pub fn new(
489		(scheduling_parent, scheduling_parent_number): (Hash, BlockNumber),
490		scheduling_ancestors: impl IntoIterator<Item = (Hash, BlockNumber)>,
491	) -> Result<Self, UnexpectedAncestor> {
492		let mut scheduling_parents = BTreeSet::new();
493
494		scheduling_parents.insert(scheduling_parent);
495
496		let mut prev = scheduling_parent_number;
497		for (ancestor, ancestor_number) in scheduling_ancestors {
498			if Some(ancestor_number) == prev.checked_sub(1) {
499				prev = ancestor_number;
500				scheduling_parents.insert(ancestor);
501			} else {
502				return Err(UnexpectedAncestor { number: ancestor_number, prev });
503			}
504		}
505
506		Ok(SchedulingScope { scheduling_parents })
507	}
508
509	/// Returns an iterator over all allowed scheduling parent hashes (scheduling parent +
510	/// ancestors).
511	pub fn scheduling_parent_hashes(&self) -> impl Iterator<Item = Hash> + '_ {
512		self.scheduling_parents.iter().copied()
513	}
514
515	/// Return if the given hash is a valid scheduling parent within this scope.
516	fn contains(&self, hash: &Hash) -> bool {
517		self.scheduling_parents.contains(hash)
518	}
519}

521/// The scope of a [`FragmentChain`].
522///
523/// This contains only the para-specific portions of the scope. The relay chain portion
524/// (scheduling parent + ancestors) is stored separately in `SchedulingScope` and passed as a
525/// parameter to methods that need it.
526#[derive(Debug, Clone)]
527pub(crate) struct Scope {
528	/// The candidates pending availability at this block.
529	pending_availability: Vec<PendingAvailability>,
530	/// The base constraints derived from the latest included candidate.
531	base_constraints: Constraints,
532	/// Maximum length of the backable chain (including candidates pending availability).
533	max_backable_len: usize,
534}
535
536impl Scope {
537	/// Define a new [`Scope`].
538	///
539	/// `max_backable_len` should be the maximum length of the backable chain (excluding
540	/// pending availability candidates).
541	pub fn new(
542		base_constraints: Constraints,
543		pending_availability: Vec<PendingAvailability>,
544		max_backable_len: usize,
545	) -> Self {
546		Scope {
547			base_constraints,
548			max_backable_len: max_backable_len + pending_availability.len(),
549			pending_availability,
550		}
551	}
552
553	/// Get the base constraints of the scope
554	pub fn base_constraints(&self) -> &Constraints {
555		&self.base_constraints
556	}
557
558	/// Whether the candidate in question is one pending availability in this scope.
559	fn get_pending_availability(
560		&self,
561		candidate_hash: &CandidateHash,
562	) -> Option<&PendingAvailability> {
563		self.pending_availability.iter().find(|c| &c.candidate_hash == candidate_hash)
564	}
565}

587impl From<&FragmentNode> for CandidateEntry {
588	fn from(node: &FragmentNode) -> Self {
589		// We don't need to perform the checks done in `CandidateEntry::new()`, since a
590		// `FragmentNode` always comes from a `CandidateEntry`
591		// Execution context: preserves relay parent for constraint validation.
592		let relay_parent = node.relay_parent();
593		Self {
594			candidate_hash: node.candidate_hash,
595			parent_head_data_hash: node.parent_head_data_hash,
596			output_head_data_hash: node.output_head_data_hash,
597			candidate: node.fragment.candidate_clone(),
598			relay_parent,
599			// Use the stored scheduling_parent from the FragmentNode
600			scheduling_parent: node.scheduling_parent,
601			// A fragment node is always backed.
602			state: CandidateState::Backed,
603			para_id: node.para_id,
604		}
605	}

608/// A candidate chain of backed/backable candidates.
609/// Includes the candidates pending availability and candidates which may be backed on-chain.
610#[derive(Default)]
611#[cfg_attr(test, derive(Clone))]
612struct BackedChain {
613	// Holds the candidate chain.
614	chain: Vec<FragmentNode>,
615	// Index from head data hash to the candidate hash with that head data as a parent.
616	// Only contains the candidates present in the `chain`.
617	by_parent_head: HashMap<Hash, CandidateHash>,
618	// Index from head data hash to the candidate hash outputting that head data.
619	// Only contains the candidates present in the `chain`.
620	by_output_head: HashMap<Hash, CandidateHash>,
621	// A set of the candidate hashes in the `chain`.
622	candidates: HashSet<CandidateHash>,
623}
624
625impl BackedChain {
626	fn push(&mut self, candidate: FragmentNode) {
627		self.candidates.insert(candidate.candidate_hash);
628		self.by_parent_head
629			.insert(candidate.parent_head_data_hash, candidate.candidate_hash);
630		self.by_output_head
631			.insert(candidate.output_head_data_hash, candidate.candidate_hash);
632		self.chain.push(candidate);
633	}
634
635	fn clear(&mut self) -> Vec<FragmentNode> {
636		self.by_parent_head.clear();
637		self.by_output_head.clear();
638		self.candidates.clear();
639
640		std::mem::take(&mut self.chain)
641	}
642
643	fn revert_to_parent_hash<'a>(
644		&'a mut self,
645		parent_head_data_hash: &Hash,
646	) -> impl Iterator<Item = FragmentNode> + 'a {
647		let mut found_index = None;
648		for index in 0..self.chain.len() {
649			let node = &self.chain[index];
650
651			if found_index.is_some() {
652				self.by_parent_head.remove(&node.parent_head_data_hash);
653				self.by_output_head.remove(&node.output_head_data_hash);
654				self.candidates.remove(&node.candidate_hash);
655			} else if &node.output_head_data_hash == parent_head_data_hash {
656				found_index = Some(index);
657			}
658		}
659
660		if let Some(index) = found_index {
661			self.chain.drain(min(index + 1, self.chain.len())..)
662		} else {
663			// Don't remove anything, but use drain to satisfy the compiler.
664			self.chain.drain(0..0)
665		}
666	}
667
668	fn contains(&self, hash: &CandidateHash) -> bool {
669		self.candidates.contains(hash)
670	}
671}

673/// This is the fragment chain specific to an active leaf.
674///
675/// It holds the current best backable candidate chain, as well as potential candidates
676/// which could become connected to the chain in the future or which could even overwrite the
677/// existing chain.
678#[cfg_attr(test, derive(Clone))]
679pub(crate) struct FragmentChain {
680	// The current scope, which dictates the on-chain operating constraints that all future
681	// candidates must adhere to.
682	scope: Scope,
683
684	// The current chain of backable candidates. It only contains candidates which build on
685	// top of each other and which have reached the backing quorum. In the presence of potential
686	// forks, this chain will pick a fork according to the `fork_selection_rule`.
687	chain: BackedChain,
688
689	// The potential candidate storage. Contains candidates which are not yet part of the `chain`
690	// but may become in the future. These can form any tree shape as well as contain any
691	// unconnected candidates for which we don't know the parent.
692	unconnected: CandidateStorage,
693}
694
695impl FragmentChain {
696	/// Create a new [`FragmentChain`] with the given scope and populate it with the candidates
697	/// pending availability.
698	pub fn init(
699		scheduling_scope: &SchedulingScope,
700		scope: Scope,
701		mut candidates_pending_availability: CandidateStorage,
702	) -> Self {
703		let mut fragment_chain =
704			Self { scope, chain: BackedChain::default(), unconnected: CandidateStorage::default() };
705
706		// We only need to populate the backable chain. Candidates pending availability must
707		// form a chain with the latest included head.
708		fragment_chain.populate_chain(scheduling_scope, &mut candidates_pending_availability);
709
710		fragment_chain
711	}
712
713	/// Populate the [`FragmentChain`] given the new candidates pending availability and the
714	/// optional previous fragment chain (of the previous scheduling parent).
715	pub fn populate_from_previous(
716		&mut self,
717		scheduling_scope: &SchedulingScope,
718		prev_fragment_chain: &FragmentChain,
719	) {
720		let mut prev_storage = prev_fragment_chain.unconnected.clone();
721
722		for candidate in prev_fragment_chain.chain.chain.iter() {
723			// If they used to be pending availability, don't add them. This is fine
724			// because:
725			// - if they still are pending availability, they have already been added to the new
726			//   storage.
727			// - if they were included, no point in keeping them.
728			//
729			// This cannot happen for the candidates in the unconnected storage. The pending
730			// availability candidates will always be part of the chain.
731			if prev_fragment_chain
732				.scope
733				.get_pending_availability(&candidate.candidate_hash)
734				.is_none()
735			{
736				let _ = prev_storage.add_candidate_entry(candidate.into());
737			}
738		}
739
740		// First populate the backable chain.
741		self.populate_chain(scheduling_scope, &mut prev_storage);
742
743		// Now that we picked the backable chain, trim the forks generated by candidates which
744		// are not present in the chain.
745		self.trim_uneligible_forks(scheduling_scope, &mut prev_storage, None);
746
747		// Finally, keep any candidates which haven't been trimmed but still have potential.
748		self.populate_unconnected_potential_candidates(scheduling_scope, prev_storage);
749	}

781	/// Return whether this candidate is backed in this chain or the unconnected storage.
782	pub fn is_candidate_backed(&self, hash: &CandidateHash) -> bool {
783		self.chain.candidates.contains(hash) ||
784			matches!(
785				self.unconnected.by_candidate_hash.get(hash),
786				Some(candidate) if candidate.state == CandidateState::Backed
787			)
788	}

790	/// Mark a candidate as backed. This can trigger a recreation of the backable chain.
791	pub fn candidate_backed(
792		&mut self,
793		scheduling_scope: &SchedulingScope,
794		newly_backed_candidate: &CandidateHash,
795	) {
796		// Already backed.
797		if self.chain.candidates.contains(newly_backed_candidate) {
798			return;
799		}
800		let Some(parent_head_hash) = self
801			.unconnected
802			.by_candidate_hash
803			.get(newly_backed_candidate)
804			.map(|entry| entry.parent_head_data_hash)
805		else {
806			// Candidate is not in unconnected storage.
807			return;
808		};
809
810		// Mark the candidate hash.
811		self.unconnected.mark_backed(newly_backed_candidate);
812
813		// Revert to parent_head_hash
814		if !self.revert_to(&parent_head_hash) {
815			// If nothing was reverted, there is nothing we can do for now.
816			return;
817		}
818
819		let mut prev_storage = std::mem::take(&mut self.unconnected);
820
821		// Populate the chain.
822		self.populate_chain(scheduling_scope, &mut prev_storage);
823
824		// Now that we picked the backable chain, trim the forks generated by candidates
825		// which are not present in the chain. We can start trimming from this candidate onwards.
826		self.trim_uneligible_forks(scheduling_scope, &mut prev_storage, Some(parent_head_hash));
827
828		// Finally, keep any candidates which haven't been trimmed but still have potential.
829		self.populate_unconnected_potential_candidates(scheduling_scope, prev_storage);
830	}

832	/// Checks if this candidate could be added in the future to this chain.
833	/// This will return `Error::CandidateAlreadyKnown` if the candidate is already in the chain or
834	/// the unconnected candidate storage.
835	pub fn can_add_candidate_as_potential(
836		&self,
837		scheduling_scope: &SchedulingScope,
838		candidate: &CandidateEntry,
839	) -> Result<(), Error> {
840		let candidate_hash = candidate.candidate_hash;
841
842		if self.chain.contains(&candidate_hash) || self.unconnected.contains(&candidate_hash) {
843			return Err(Error::CandidateAlreadyKnown);
844		}
845
846		self.check_potential(scheduling_scope, candidate)
847	}

849	/// Lightweight check for whether a hypothetical candidate (possibly incomplete) could be added
850	/// to this chain. Only performs checks that don't require the relay parent or full candidate
851	/// data: scheduling parent in scope, fork checks, cycle checks.
852	pub fn can_add_candidate_as_potential_hypothetical(
853		&self,
854		scheduling_scope: &SchedulingScope,
855		scheduling_parent: Hash,
856		maybe_relay_parent: Option<&RelayParentInfo>,

867			scheduling_parent,
868			maybe_relay_parent,
869			candidate_hash,
870			parent_head_hash,
871			output_head_hash,
872		)?;

878	/// the chain directly in the seconded state, it will only be part of the unconnected storage.
879	pub fn try_adding_seconded_candidate(
880		&mut self,
881		scheduling_scope: &SchedulingScope,
882		candidate: &CandidateEntry,
883	) -> Result<(), Error> {
884		if candidate.state == CandidateState::Backed {
885			return Err(Error::IntroduceBackedCandidate);
886		}
887
888		self.can_add_candidate_as_potential(scheduling_scope, candidate)?;
889
890		// This clone is cheap, as it uses an Arc for the expensive stuff.
891		// We can't consume the candidate because other fragment chains may use it also.
892		self.unconnected.add_candidate_entry(candidate.clone())?;
893
894		Ok(())
895	}

897	/// Try getting the full head data associated with this hash.
898	pub fn get_head_data_by_hash(&self, head_data_hash: &Hash) -> Option<HeadData> {
899		// First, see if this is the head data of the latest included candidate.
900		let required_parent = &self.scope.base_constraints().required_parent;
901		if &required_parent.hash() == head_data_hash {
902			return Some(required_parent.clone());
903		}
904
905		// Cheaply check if the head data is in the chain.
906		let has_head_data_in_chain = self
907			.chain
908			.by_parent_head
909			.get(head_data_hash)
910			.or_else(|| self.chain.by_output_head.get(head_data_hash))
911			.is_some();
912
913		if has_head_data_in_chain {
914			return self.chain.chain.iter().find_map(|candidate| {
915				if &candidate.parent_head_data_hash == head_data_hash {
916					Some(
917						candidate
918							.fragment
919							.candidate()
920							.persisted_validation_data
921							.parent_head
922							.clone(),
923					)
924				} else if &candidate.output_head_data_hash == head_data_hash {
925					Some(candidate.fragment.candidate().commitments.head_data.clone())
926				} else {
927					None
928				}
929			});
930		}
931
932		// Lastly, try getting the head data from the unconnected candidates.
933		self.unconnected.head_data_by_hash(head_data_hash).cloned()
934	}

936	/// Select `count` candidates after the given `ancestors` which can be backed on chain next.
937	///
938	/// The intention of the `ancestors` is to allow queries on the basis of
939	/// one or more candidates which were previously pending availability becoming
940	/// available or candidates timing out.
941	///
942	/// Returns a vector of backable candidate references containing the candidate hash
943	/// and scheduling parent (used for validator group assignment).
944	pub fn find_backable_chain(
945		&self,
946		ancestors: Ancestors,
947		count: u32,
948	) -> Vec<BackableCandidateRef> {
949		if count == 0 {
950			return vec![];
951		}
952		let base_pos = self.find_ancestor_path(ancestors);
953
954		let actual_end_index = std::cmp::min(base_pos + (count as usize), self.chain.chain.len());
955		let mut res = Vec::with_capacity(actual_end_index - base_pos);
956
957		for elem in &self.chain.chain[base_pos..actual_end_index] {
958			// Only supply candidates which are not yet pending availability. `ancestors` should
959			// have already contained them, but check just in case.
960			if self.scope.get_pending_availability(&elem.candidate_hash).is_none() {
961				res.push(BackableCandidateRef {
962					candidate_hash: elem.candidate_hash,
963					scheduling_parent: elem.scheduling_parent,
964				});
965			} else {
966				break;
967			}
968		}
969
970		res
971	}

973	// Tries to orders the ancestors into a viable path from root to the last one.
974	// Stops when the ancestors are all used or when a node in the chain is not present in the
975	// ancestor set. Returns the index in the chain were the search stopped.
976	fn find_ancestor_path(&self, mut ancestors: Ancestors) -> usize {
977		if self.chain.chain.is_empty() {
978			return 0;
979		}
980
981		for (index, candidate) in self.chain.chain.iter().enumerate() {
982			if !ancestors.remove(&candidate.candidate_hash) {
983				return index;
984			}
985		}
986
987		// This means that we found the entire chain in the ancestor set. There won't be anything
988		// left to back.
989		self.chain.chain.len()
990	}
991
992	// Return the earliest relay parent a new candidate can have in order to be added to the chain
993	// right now. This is the relay parent of the last candidate in the chain.
994	// The value returned may not be valid if we want to add a candidate pending availability, which
995	// may have a relay parent which is out of scope. Special handling is needed in that case.
996	// Execution context: the relay parent determines constraint progression
997	// (HRMP watermark, DMP advancement must not regress).
998	fn earliest_relay_parent_number(&self) -> BlockNumber {
999		if let Some(last_candidate) = self.chain.chain.last() {
1000			last_candidate.fragment.relay_parent().number
1001		} else {
1002			self.scope.base_constraints.min_relay_parent_number
1003		}
1004	}
1005
1006	// Return the earliest relay parent a potential candidate may have for it to ever be added to
1007	// the chain. This is the relay parent of the last candidate pending availability or the
1008	// earliest relay parent in scope.
1009	fn earliest_relay_parent_pending_availability(&self) -> Option<&RelayParentInfo> {
1010		self.chain.chain.iter().rev().find_map(|candidate| {
1011			self.scope
1012				.get_pending_availability(&candidate.candidate_hash)
1013				.map(|c| &c.relay_parent)
1014		})
1015	}

1017	// Populate the unconnected potential candidate storage starting from a previous storage.
1018	fn populate_unconnected_potential_candidates(
1019		&mut self,
1020		scheduling_scope: &SchedulingScope,
1021		old_storage: CandidateStorage,
1022	) {
1023		for candidate in old_storage.by_candidate_hash.into_values() {
1024			// Sanity check, all pending availability candidates should be already present in the
1025			// chain.
1026			if self.scope.get_pending_availability(&candidate.candidate_hash).is_some() {
1027				continue;
1028			}
1029
1030			match self.can_add_candidate_as_potential(scheduling_scope, &candidate) {
1031				Ok(()) => {
1032					let _ = self.unconnected.add_candidate_entry(candidate);
1033				},
1034				Err(e) => {
1035					let msg = format!("Failed to add candidate as potential err={:?}, candidate_hash={:?}, para_id={:?}", e, candidate.candidate_hash, candidate.para_id);
1036					if e.is_relay_block_not_in_scope() {
1037						gum::debug!(target: LOG_TARGET, msg);
1038					} else {
1039						gum::trace!(target: LOG_TARGET, msg);
1040					};
1041				},
1042			};
1043		}
1044	}

1046	// Check whether a candidate outputting this head data would introduce a cycle or multiple paths
1047	// to the same state. Trivial 0-length cycles are checked in `CandidateEntry::new`.
1048	fn check_cycles_or_invalid_tree(&self, output_head_hash: &Hash) -> Result<(), Error> {
1049		// this should catch a cycle where this candidate would point back to the parent of some
1050		// candidate in the chain.
1051		if self.chain.by_parent_head.contains_key(output_head_hash) {
1052			return Err(Error::Cycle);
1053		}
1054
1055		// multiple paths to the same state, which can't happen for a chain.
1056		if self.chain.by_output_head.contains_key(output_head_hash) {
1057			return Err(Error::MultiplePaths);
1058		}
1059
1060		Ok(())
1061	}

1063	// Lightweight potential check using only scheduling_parent and parent/output head hashes.
1064	// Used for hypothetical (possibly incomplete) candidates where we don't have the relay parent
1065	// or full candidate data. Checks: scheduling parent in scope, zero-length cycle, fork rules,
1066	// cycle/invalid tree checks.
1067	fn check_potential_lightweight(
1068		&self,
1069		scheduling_scope: &SchedulingScope,
1070		scheduling_parent: Hash,
1071		maybe_relay_parent: Option<&RelayParentInfo>,
1072		candidate_hash: CandidateHash,
1073		parent_head_hash: Hash,
1074		output_head_hash: Option<Hash>,
1075	) -> Result<Option<(bool, Constraints)>, Error> {
1076		// Check if the scheduling parent is in scope.
1077		if !scheduling_scope.contains(&scheduling_parent) {
1078			return Err(Error::SchedulingParentNotInScope(scheduling_parent));
1079		}
1080
1081		// Trivial 0-length cycle.
1082		if let Some(output_head_hash) = output_head_hash {
1083			if parent_head_hash == output_head_hash {
1084				return Err(Error::ZeroLengthCycle);
1085			}
1086		}
1087
1088		// If it's a fork with a backed candidate in the current chain.
1089		if let Some(other_candidate) = self.chain.by_parent_head.get(&parent_head_hash) {
1090			if self.scope().get_pending_availability(other_candidate).is_some() {
1091				// Cannot accept a fork with a candidate pending availability.
1092				return Err(Error::ForkWithCandidatePendingAvailability(*other_candidate));
1093			}
1094
1095			// If the candidate is backed and in the current chain, accept only a candidate
1096			// according to the fork selection rule.
1097			if fork_selection_rule(other_candidate, &candidate_hash) == Ordering::Less {
1098				return Err(Error::ForkChoiceRule(*other_candidate));
1099			}
1100		}
1101
1102		// Check for cycles or invalid tree transitions.
1103		if let Some(ref output_head_hash) = output_head_hash {
1104			self.check_cycles_or_invalid_tree(output_head_hash)?;
1105		}
1106
1107		let Some(relay_parent) = maybe_relay_parent else {
1108			// Nothing more to check if we don't know the relay parent yet.
1109			return Ok(None);
1110		};
1111
1112		// Check if the relay parent moved backwards from the latest candidate pending availability.
1113		if let Some(earliest_rp_of_pending_availability) =
1114			self.earliest_relay_parent_pending_availability()
1115		{
1116			if relay_parent.number < earliest_rp_of_pending_availability.number {
1117				return Err(Error::RelayParentPrecedesCandidatePendingAvailability(
1118					relay_parent.hash,
1119					earliest_rp_of_pending_availability.hash,
1120				));
1121			}
1122		}
1123
1124		// Try seeing if the parent candidate is in the current chain or if it is the latest
1125		// included candidate. If so, get the constraints the candidate must satisfy.
1126		let (is_unconnected, constraints, maybe_min_relay_parent_number) =
1127			if let Some(parent_candidate) = self.chain.by_output_head.get(&parent_head_hash) {
1128				let Some(parent_candidate) =
1129					self.chain.chain.iter().find(|c| &c.candidate_hash == parent_candidate)
1130				else {
1131					// Should never really happen.
1132					return Err(Error::ParentCandidateNotFound);
1133				};
1134
1135				(
1136					false,
1137					self.scope
1138						.base_constraints
1139						.apply_modifications(&parent_candidate.cumulative_modifications)
1140						.map_err(Error::ComputeConstraints)?,
1141					// Execution context: relay parent block number for HRMP
1142					// watermark and DMP constraint checking.
1143					Some(parent_candidate.fragment.relay_parent().number),
1144				)
1145			} else if self.scope.base_constraints.required_parent.hash() == parent_head_hash {
1146				// It builds on the latest included candidate.
1147				(false, self.scope.base_constraints.clone(), None)
1148			} else {
1149				// The parent is not yet part of the chain
1150				(true, self.scope.base_constraints.clone(), None)
1151			};
1152
1153		// Execution context: check if the relay parent is in scope.
1154		if relay_parent.number < constraints.min_relay_parent_number {
1155			return Err(Error::RelayParentNotInScope(relay_parent.hash));
1156		}
1157
1158		if let Some(earliest_rp) = maybe_min_relay_parent_number {
1159			if relay_parent.number < earliest_rp {
1160				return Err(Error::RelayParentMovedBackwards);
1161			}
1162		}
1163
1164		Ok(Some((is_unconnected, constraints)))
1165	}
1166
1167	// Full potential check for concrete candidates (CandidateEntry). Performs all lightweight
1168	// checks plus relay-parent-dependent validation: relay parent in scope, constraint checking,
1169	// min relay parent number checks.
1170	fn check_potential(
1171		&self,
1172		scheduling_scope: &SchedulingScope,
1173		candidate: &CandidateEntry,
1174	) -> Result<(), Error> {
1175		let parent_head_hash = candidate.parent_head_data_hash;
1176		let relay_parent = candidate.relay_parent_info();
1177
1178		// Run the lightweight checks first.
1179		let (is_unconnected, constraints) = self
1180			.check_potential_lightweight(
1181				scheduling_scope,
1182				candidate.scheduling_parent,
1183				Some(&relay_parent),
1184				candidate.candidate_hash,
1185				parent_head_hash,
1186				Some(candidate.output_head_data_hash),
1187			)?
1188			.ok_or_else(|| {
1189				debug_assert!(
1190					false,
1191					"Not possible. We passed in a relay parent so we will get the constraints back"
1192				);
1193				Error::RelayParentNotInScope(relay_parent.hash)
1194			})?;
1195
1196		// Check against constraints.
1197		let commitments = &candidate.candidate.commitments;
1198		let pvd = &candidate.candidate.persisted_validation_data;
1199		let validation_code_hash = candidate.candidate.validation_code_hash;
1200
1201		if is_unconnected {
1202			// If the parent is not yet part of the chain, we can only check the commitments.
1203			return validate_commitments(
1204				&constraints,
1205				&relay_parent,
1206				commitments,
1207				&validation_code_hash,
1208			)
1209			.map_err(Error::CheckAgainstConstraints);
1210		}
1211		Fragment::check_against_constraints(
1212			&relay_parent,
1213			&constraints,
1214			commitments,
1215			&validation_code_hash,
1216			pvd,
1217		)
1218		.map_err(Error::CheckAgainstConstraints)?;
1219
1220		Ok(())
1221	}
1222
1223	// Once the backable chain was populated, trim the forks generated by candidates which
1224	// are not present in the chain. Fan this out into a full breadth-first search.
1225	// If `starting_point` is `Some()`, start the search from the candidates having this parent head
1226	// hash.
1227	fn trim_uneligible_forks(
1228		&self,
1229		scheduling_scope: &SchedulingScope,
1230		storage: &mut CandidateStorage,
1231		starting_point: Option<Hash>,
1232	) {
1233		// Start out with the candidates in the chain. They are all valid candidates.
1234		let mut queue: VecDeque<_> = if let Some(starting_point) = starting_point {
1235			[(starting_point, true)].into_iter().collect()
1236		} else {
1237			if self.chain.chain.is_empty() {
1238				[(self.scope.base_constraints.required_parent.hash(), true)]
1239					.into_iter()
1240					.collect()
1241			} else {
1242				self.chain.chain.iter().map(|c| (c.parent_head_data_hash, true)).collect()
1243			}
1244		};
1245		// To make sure that cycles don't make us loop forever, keep track of the visited parent
1246		// heads.
1247		let mut visited = HashSet::new();
1248
1249		while let Some((parent, parent_has_potential)) = queue.pop_front() {
1250			visited.insert(parent);
1251
1252			let Some(children) = storage.by_parent_head.get(&parent) else { continue };
1253			// Cannot remove while iterating so store them here temporarily.
1254			let mut to_remove = vec![];
1255
1256			for child_hash in children.iter() {
1257				let Some(child) = storage.by_candidate_hash.get(child_hash) else { continue };
1258
1259				// Already visited this parent. Either is a cycle or multiple paths that lead to the
1260				// same candidate. Either way, stop this branch to avoid looping forever.
1261				if visited.contains(&child.output_head_data_hash) {
1262					continue;
1263				}
1264
1265				// Only keep a candidate if its full ancestry was already kept as potential and this
1266				// candidate itself has potential.
1267				let mut keep = false;
1268				if parent_has_potential {
1269					match self.check_potential(scheduling_scope, child) {
1270						Ok(()) => {
1271							keep = true;
1272						},
1273						Err(e) => {
1274							gum::debug!(
1275								target: LOG_TARGET,
1276								candidate_hash = ?child_hash,
1277								para_id = ?child.para_id,
1278								parent = ?parent,
1279								err = ?e,
1280								"check_potential failed for candidate"
1281							);
1282						},
1283					}
1284				}
1285
1286				if keep {
1287					queue.push_back((child.output_head_data_hash, true));
1288				} else {
1289					// Otherwise, remove this candidate and continue looping for its children, but
1290					// mark the parent's potential as `false`. We only want to remove its
1291					// children.
1292					to_remove.push(*child_hash);
1293					queue.push_back((child.output_head_data_hash, false));
1294				}
1295			}
1296
1297			for hash in to_remove {
1298				storage.remove_candidate(&hash);
1299			}
1300		}
1301	}
1302
1303	// Populate the fragment chain with candidates from the supplied `CandidateStorage`.
1304	// Can be called by the constructor or when backing a new candidate.
1305	// When this is called, it may cause the previous chain to be completely erased or it may add
1306	// more than one candidate.
1307	fn populate_chain(
1308		&mut self,
1309		scheduling_scope: &SchedulingScope,
1310		storage: &mut CandidateStorage,
1311	) {
1312		struct Candidate {
1313			para_id: ParaId,
1314			fragment: Fragment,
1315			candidate_hash: CandidateHash,
1316			output_head_data_hash: Hash,
1317			parent_head_data_hash: Hash,
1318			scheduling_parent: Hash,
1319		}
1320
1321		let mut cumulative_modifications = if let Some(last_candidate) = self.chain.chain.last() {
1322			last_candidate.cumulative_modifications.clone()
1323		} else {
1324			ConstraintModifications::identity()
1325		};
1326
1327		let mut earliest_rp = self.earliest_relay_parent_number();
1328
1329		loop {
1330			if self.chain.chain.len() >= self.scope.max_backable_len {
1331				break;
1332			}
1333
1334			let child_constraints =
1335				match self.scope.base_constraints.apply_modifications(&cumulative_modifications) {
1336					Err(e) => {
1337						gum::debug!(
1338							target: LOG_TARGET,
1339							new_parent_head = ?cumulative_modifications.required_parent,
1340							err = ?e,
1341							"Failed to apply modifications",
1342						);
1343
1344						break;
1345					},
1346					Ok(c) => c,
1347				};
1348
1349			let required_head_hash = child_constraints.required_parent.hash();
1350
1351			// Select the few possible backed/backable children which can be added to the chain
1352			// right now.
1353			let possible_children = storage
1354				.possible_backed_para_children(&required_head_hash)
1355				.filter_map(|candidate| {
1356					// Only select a candidate if:
1357					// 1. it does not introduce a fork or a cycle.
1358					// 2. parent hash is correct.
1359					// 3. relay-parent does not move backwards.
1360					// 4. all non-pending-availability candidates have relay-parent in scope.
1361					// 5. candidate outputs fulfill constraints
1362
1363					let pending = self.scope.get_pending_availability(&candidate.candidate_hash);
1364
1365					// For non-pending candidates, scheduling parent must be in scope.
1366					// Pending availability candidates may have out-of-scope scheduling parents —
1367					// they're already on-chain and don't need to satisfy the current scope.
1368					if pending.is_none() && !scheduling_scope.contains(&candidate.scheduling_parent)
1369					{
1370						return None;
1371					}
1372
1373					let relay_parent = pending
1374						.map(|p| p.relay_parent.clone())
1375						.unwrap_or_else(|| candidate.relay_parent_info());
1376
1377					if self.check_cycles_or_invalid_tree(&candidate.output_head_data_hash).is_err()
1378					{
1379						return None;
1380					}
1381
1382					// require: candidates don't move backwards in terms of relay parent number
1383					// and only pending availability candidates can be out-of-scope.
1384					//
1385					// earliest_rp can be before the earliest relay parent in the scope
1386					// when the parent is a pending availability candidate as well, but
1387					// only other pending candidates can have a relay parent out of scope.
1388					let min_relay_parent_number = pending
1389						.map(|p: &PendingAvailability| match self.chain.chain.len() {
1390							0 => p.relay_parent.number,
1391							_ => earliest_rp,
1392						})
1393						.unwrap_or(earliest_rp);
1394
1395					if relay_parent.number < min_relay_parent_number {
1396						return None; // relay parent moved backwards.
1397					}
1398
1399					// Note: we intentionally do NOT check that scheduling_parent
1400					// advances between candidates. Scheduling_parent backwards
1401					// movement is primarily a censorship resistance concern, which
1402					// is handled by the collator protocol's slot-based check
1403					// (validators reject advertisements where the scheduling_parent
1404					// does not correspond to the last finished relay chain slot).
1405					// The scheduling_parent may not be the tip of a fork (e.g. when
1406					// a new relay block arrives mid-slot), which is still valid.
1407					// From the relay chain's perspective, we only require that the
1408					// scheduling_parent is within allowed scheduling parents.
1409					// don't add candidates if they're already present in the chain.
1410					// this can never happen, as candidates can only be duplicated if there's a
1411					// cycle and we shouldn't have allowed for a cycle to be chained.
1412					if self.chain.contains(&candidate.candidate_hash) {
1413						return None;
1414					}
1415
1416					let fragment = {
1417						let mut constraints = child_constraints.clone();
1418						if let Some(ref p) = pending {
1419							// overwrite for candidates pending availability as a special-case.
1420							constraints.min_relay_parent_number = p.relay_parent.number;
1421						}
1422
1423						let f = Fragment::new(
1424							relay_parent.clone(),
1425							constraints,
1426							// It's cheap to clone because it's wrapped in an Arc
1427							candidate.candidate.clone(),
1428						);
1429
1430						match f {
1431							Ok(f) => f,
1432							Err(e) => {
1433								gum::debug!(
1434									target: LOG_TARGET,
1435									err = ?e,
1436									?relay_parent,
1437									para_id = ?candidate.para_id,
1438									candidate_hash = ?candidate.candidate_hash,
1439									"Failed to instantiate fragment",
1440								);
1441
1442								return None;
1443							},
1444						}
1445					};
1446
1447					let para_id = candidate.para_id;
1448					let scheduling_parent = candidate.scheduling_parent;
1449
1450					Some(Candidate {
1451						para_id,
1452						fragment,
1453						candidate_hash: candidate.candidate_hash,
1454						output_head_data_hash: candidate.output_head_data_hash,
1455						parent_head_data_hash: candidate.parent_head_data_hash,
1456						scheduling_parent,
1457					})
1458				});
1459
1460			// Choose the best candidate.
1461			let best_candidate = possible_children.min_by(|lhs, rhs| {
1462				let child1 = &lhs.candidate_hash;
1463				let child2 = &rhs.candidate_hash;
1464				// Always pick a candidate pending availability as best.
1465				if self.scope.get_pending_availability(child1).is_some() {
1466					Ordering::Less
1467				} else if self.scope.get_pending_availability(child2).is_some() {
1468					Ordering::Greater
1469				} else {
1470					// Otherwise, use the fork selection rule.
1471					fork_selection_rule(child1, child2)
1472				}
1473			});
1474
1475			if let Some(Candidate {
1476				para_id,
1477				fragment,
1478				candidate_hash,
1479				output_head_data_hash,
1480				parent_head_data_hash,
1481				scheduling_parent,
1482			}) = best_candidate
1483			{
1484				// Remove the candidate from storage.
1485				storage.remove_candidate(&candidate_hash);
1486
1487				// Update the cumulative constraint modifications.
1488				cumulative_modifications.stack(fragment.constraint_modifications());
1489				// Execution context: track earliest relay parent for constraint validation.
1490				earliest_rp = fragment.relay_parent().number;
1491
1492				let node = FragmentNode {
1493					fragment,
1494					candidate_hash,
1495					parent_head_data_hash,
1496					output_head_data_hash,
1497					cumulative_modifications: cumulative_modifications.clone(),
1498					scheduling_parent,
1499					para_id,
1500				};
1501
1502				// Add the candidate to the chain now.
1503				self.chain.push(node);
1504			} else {
1505				break;
1506			}
1507		}
1508	}
1509
1510	// Revert the backable chain so that the last candidate will be one outputting the given
1511	// `parent_head_hash`. If the `parent_head_hash` is exactly the required parent of the base
1512	// constraints (builds on the latest included candidate), revert the entire chain.
1513	// Return false if we couldn't find the parent head hash.
1514	fn revert_to(&mut self, parent_head_hash: &Hash) -> bool {
1515		let mut removed_items = None;
1516		if &self.scope.base_constraints.required_parent.hash() == parent_head_hash {
1517			removed_items = Some(self.chain.clear());
1518		}
1519
1520		if removed_items.is_none() && self.chain.by_output_head.contains_key(parent_head_hash) {
1521			removed_items = Some(self.chain.revert_to_parent_hash(parent_head_hash).collect());
1522		}
1523
1524		let Some(removed_items) = removed_items else { return false };
1525
1526		// Even if it's empty, we need to return true, because we'll be able to add a new candidate
1527		// to the chain.
1528		for node in &removed_items {
1529			let _ = self.unconnected.add_candidate_entry(node.into());
1530		}
1531		true
1532	}
1533}
