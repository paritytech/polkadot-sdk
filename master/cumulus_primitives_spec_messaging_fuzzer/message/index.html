The off-chain response verifiers in message.

MessageOracle commits STREAMS streams under N successive StreamsRoots. At height h stream 0 has h leaves, stream 1 h / 2 and stream 2 h / 3; a stream with none is left out of the tree. Streams 0 and 1 share leaves (leaf version 0), stream 2 hashes the same payloads as version 1, so material for one stream can be offered for another. A fourth stream is never committed.

Responses start honest, then take arbitrary edits. Whenever a verifier accepts one under a real StreamsRoot, the claim behind it must hold:

  • FORGERY: payloads, a position or a frontier the committed stream does not have.
  • MALLEABLE: the right answer, from material other than the honest proof.

An accepted response must also honour its request.

  • message_fetch: [verify_messages].
  • message_event: [verify_event], head and positional reads.
  • message_decode: wire bytes through [verify_exchange]. Every decoded value must be canonical (NONCANONICAL). Seed it with honest encodings first, from this crate: SEED_DIR=hfuzz_workspace/message_decode/input cargo test write_decode_seeds -- --ignored
