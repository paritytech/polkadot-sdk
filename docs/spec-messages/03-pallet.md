# Speculative Messaging: Pallet

**Location:** `cumulus/pallets/speculative-messaging/`

**Crate:** `cumulus-pallet-speculative-messaging`

This pallet implements the on-chain sender/receiver logic for speculative messaging within a parachain runtime. It maintains per-destination MMRs for outgoing messages, tracks per-source state for incoming messages, and emits provides/requires commitments consumed by `pallet-parachain-system`.

## Config Trait

```rust
#[pallet::config]
pub trait Config: frame_system::Config {
    #[pallet::constant]
    type MaxDestinations: Get<u32>;       // Max destination chains (e.g. 100)

    #[pallet::constant]
    type MaxSources: Get<u32>;            // Max sources per block (e.g. 100)

    #[pallet::constant]
    type MaxMessagesPerBlock: Get<u32>;   // Max messages to one dest per block (e.g. 1000)

    #[pallet::constant]
    type MaxPayloadSize: Get<u32>;        // Max payload bytes per message (e.g. 1024)
}
```

## Storage Items

### Sender-Side (Persistent)

```
DestinationMmrs: StorageMap<ParaId, MmrState>
```
Per-destination MMR state (leaf count + peaks). Grows monotonically as messages are sent.

```
TopLevelTree: StorageValue<StoredMerkleTree>
```
Binary Merkle tree over all per-destination MMR roots. Its root is the `ProvidesCommitment`.

### Sender-Side (Ephemeral — cleared each block)

```
PendingOutgoing: StorageMap<ParaId, Vec<OutgoingMessage>>
```
Messages sent during the current block, keyed by destination. Read by collator networking layer for off-chain distribution. Cleared in `on_initialize`.

### Receiver-Side (Persistent)

```
PerSourceState: StorageMap<ParaId, SourceState>
```
Tracks `last_processed` count and `last_seen_root` per source chain.

### Receiver-Side (Ephemeral — cleared each block)

```
PendingRequires: StorageValue<Vec<RequiresCommitment>>
```
`RequiresCommitment`s accumulated during this block. Cleared in `on_initialize`.

### Peer Registry

```
RelayPeers: StorageMap<ParaId, BoundedVec<u8, ConstU32<MAX_PEER_ID_LEN>>>
```
Maps destination ParaId to relay chain peer identity bytes. Configured via sudo extrinsics (MVP).

## Storage Lifecycle Diagram

```
on_initialize(block N):
  PendingOutgoing.clear()
  PendingRequires.clear()

Block N execution:
  send_message() calls:
    DestinationMmrs[dest] += leaf        (persistent, grows)
    TopLevelTree.update(dest, new_root)  (persistent, updated)
    PendingOutgoing[dest].push(msg)      (ephemeral, for networking)

  receive_messages() calls:
    PerSourceState[source].advance()     (persistent, grows)
    PendingRequires.push(commitment)     (ephemeral, for commitments)

on_finalize(block N):  [via pallet-parachain-system]
  provides_root() reads TopLevelTree.root()
  requires_commitments() reads PendingRequires

on_initialize(block N+1):
  PendingOutgoing.clear()   <- collator had time to read these
  PendingRequires.clear()   <- already collected by on_finalize
```

## Hooks

### on_initialize

Clears ephemeral storage: `PendingOutgoing` (all entries) and `PendingRequires`.

Uses `u32::MAX` removal limit to guarantee cleanup even after runtime upgrades.

## Internal Functions

### send_message(destination, payload) -> Result<(u64, H256)>

This is the core sender-side logic:

```
1. Validate payload.len() <= MaxPayloadSize
2. Check per-block message count for dest < MaxMessagesPerBlock
3. Load or create MmrState from DestinationMmrs[dest]
4. Create OutgoingMessage { destination, payload, position: mmr.leaf_count }
5. Compute leaf_hash = OutgoingMessage::leaf_hash()   [0x03 domain prefix]
6. Push leaf into MMR:
   a. current = leaf_hash
   b. For each trailing 1-bit in leaf_count:
      - Pop rightmost peak
      - current = merge_mmr_nodes(peak, current)   [0x02 domain prefix]
   c. Push current as new peak
   d. Increment leaf_count
7. Update TopLevelTree:
   a. If new destination (not in tree):
      - Check destination count < MaxDestinations
      - tree.upsert(dest, new_mmr_root)   [O(D) rebuild]
      - Emit DestinationAdded event
   b. If existing destination:
      - tree.update(dest, new_mmr_root)   [O(log D) rehash]
8. Save MmrState to DestinationMmrs[dest]
9. Append message to PendingOutgoing[dest]
10. Emit MessageSent { destination, position, leaf_hash }
11. Return (position, leaf_hash)
```

### receive_messages(source, count, provides_root) -> Result<()>

Core receiver-side logic:

```
1. Validate count > 0 (reject empty batch)
2. Check PendingRequires.len() < MaxSources
3. Check no duplicate source in this block
4. Mutate PerSourceState[source]:
   a. SourceState::advance(count, provides_root)
   b. Uses checked_add for overflow safety
5. Push RequiresCommitment { source, expected_root: provides_root }
   into PendingRequires
6. Emit MessagesReceived { source, count, provides_root }
```

## Per-Destination MMR (`per_dest_mmr.rs`)

### MmrState

```rust
pub struct MmrState {
    pub leaf_count: u64,
    pub peaks: Vec<H256>,
}
```

**Invariant:** An MMR with `n` leaves has exactly `n.count_ones()` peaks (number of 1-bits in binary representation of n).

### push(leaf_hash) -> H256

```
current = leaf_hash
pos = leaf_count

while pos has trailing 1-bit:
    left_sibling = peaks.pop()
    current = merge_mmr_nodes(left_sibling, current)
    pos >>= 1

peaks.push(current)
leaf_count += 1
return bag_peaks(&peaks)
```

### root() -> H256

```rust
bag_peaks(&self.peaks)
```

Peaks are bagged right-to-left using `merge_mmr_nodes` (0x02 domain prefix).

### MMR Growth Example

```
After push(m0): leaf_count=1 (0b1), peaks=[m0]
  root = m0

After push(m1): leaf_count=2 (0b10), peaks=[merge(m0,m1)]
  root = merge(m0,m1)

After push(m2): leaf_count=3 (0b11), peaks=[merge(m0,m1), m2]
  root = merge_mmr_nodes(merge(m0,m1), m2)  [bagged right-to-left]

After push(m3): leaf_count=4 (0b100), peaks=[merge(merge(m0,m1),merge(m2,m3))]
  root = merge(merge(m0,m1),merge(m2,m3))
```

## SpeculativeMessagingProvider Implementation

```rust
impl<T: Config> SpeculativeMessagingProvider for Pallet<T> {
    fn provides_root() -> Option<H256> {
        let root = TopLevelTree::<T>::get().root();
        if root == H256::zero() { None } else { Some(root) }
    }

    fn requires_commitments() -> Vec<RequiresCommitment> {
        PendingRequires::<T>::get()
    }
}
```

Called by `pallet-parachain-system` in `on_finalize` to collect commitments for the `ValidationResult`.

## Error Types

pub enum Error<T> {
    TooManyDestinations,        // Would exceed MaxDestinations

## Inherent Support

**Identifier:** `b"specmsg0"`

**InherentType:** `Vec<(ParaId, u64, H256)>` — tuples of `(source_para_id, message_count, provides_root)`

```rust
impl<T: Config> ProvideInherent for Pallet<T> {
    fn create_inherent(data: &InherentData) -> Option<Self::Call> {
        let entries: InherentType = data.get_data(&INHERENT_IDENTIFIER)?;
        if entries.is_empty() { return None; }
        Some(Call::receive_messages_inherent { entries })
    }
}
```

The `SpecMsgInherentDataProvider` (client-side) populates the inherent data from off-chain message batches collected by the networking layer.

## Diagram: Full Pallet Data Flow

```
                SENDER SIDE                          RECEIVER SIDE
                ===========                          =============

  User/XCM                                     Inherent (from collator)
      |                                                |
      v                                                v
  send_message_extrinsic                    receive_messages_inherent
      |                                                |
      v                                                v
  send_message(dest, payload)               receive_messages(source, count, root)
      |                                                |
      +-> MmrState.push(leaf_hash)                     +-> SourceState.advance(count, root)
      |       |                                        |
      |       v                                        v
      |   DestinationMmrs[dest]                   PerSourceState[source]
      |                                                |
      +-> TopLevelTree.update(dest, new_root)          +-> PendingRequires.push(commitment)
      |       |
      |       v
      |   TopLevelTree (StoredMerkleTree)
      |
      +-> PendingOutgoing[dest].push(msg)
              |
              v
         Collator networking reads this
         and distributes off-chain
              |                                   on_finalize:
              |                                     provides_root() -> TopLevelTree.root()
              |                                     requires_commitments() -> PendingRequires
              v
    on_initialize (next block):
      PendingOutgoing.clear()
      PendingRequires.clear()
```
